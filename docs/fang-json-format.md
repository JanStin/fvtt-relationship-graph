# FANG JSON format

Источник: `fang.json` (экспорт из FANG). Пример реального мира лежит в корне.

## Структура
- `nodes[]` — персонажи (актёры и плейсхолдеры)
- `links[]` — связи между узлами
- `factions[]` — фракции
- `zones[]` — зоны, **не поддерживаем, игнорируем при импорте**
- `relationshipTypes[]` — справочник типов связей
- `showFactionLines`, `showFactionLegend` — флаги, можно игнорировать

## Ключевые решения для импорта
1. `isPlaceholder: true` (и `actorId: null`) — виртуальные NPC, сохраняем как отдельный тип узла.
2. Для отображения берём `name`, `originalName` храним как есть.
3. `factionIds` — массив, узел может быть в нескольких фракциях. Приоритет для фонового цвета — по первому элементу массива.
4. `conditions` — свободный список строк, не валидируем жёстко. Строки становятся id состояний; те, которых нет во встроенном наборе, при импорте добавляются в справочник (`GraphData.conditions`) с иконкой по умолчанию.
5. `links[].source/target` и `factionId` ссылаются на `nodes[].id` и `factions[].id`. Проверяем целостность, битые ссылки — в лог и пропускаем.
6. `vx`, `vy` — сбрасываем в 0.
7. Отсутствующие поля не должны ломать парсер — используем дефолты.
8. Все id — строки, не полагаемся на порядок в массивах.
9. `img: "modules/fang/assets/placeholder-npc.svg"` — заглушка FANG для узлов без картинки; при импорте превращается в пустой `img` (свою заглушку подставляет рендер).

## Поля узлов, которые нам реально нужны
`id`, `actorId`, `isPlaceholder`, `img`, `name`, `originalName`, `x`, `y`,
`factionId`, `factionIds`, `role`, `lore`, `playerNotes`, `conditions`,
`hidden`, `gmOnly`, `isCenter`.

Остальные — сохраняем как есть, но не используем.

## Поля фракций
`id`, `name`, `color`, `description`. `playerVisible` не переносим — у нас фракции видны всем.
