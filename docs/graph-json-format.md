# Формат файла графа (экспорт модуля)

Собственный формат модуля для экспорта и импорта без потерь. Код —
`src/import/native.ts`, тесты — `tests/import/native.test.ts`. Формат экспорта FANG описан
отдельно — `docs/fang-json-format.md`.

## Верхний уровень

```json
{
  "format": "fvtt-relationship-graph",
  "version": 1,
  "exportedAt": "2026-09-30T12:00:00.000Z",
  "data": { "nodes": [], "edges": [], "factions": [], "relationshipTypes": [], "conditions": [] }
}
```

| Поле | Что это |
| --- | --- |
| `format` | Маркер. По нему импорт отличает свой файл от FANG: есть маркер — свой формат, нет — FANG. |
| `version` | Версия формата. Файл новее, чем знает модуль, не импортируется (ошибка «обновите модуль»). |
| `exportedAt` | Дата экспорта, только для человека. |
| `data` | `GraphData` как есть — та же структура, что хранится в журнале (`src/core/model.ts`). |

`data` — граф целиком, включая то, что игроки не видят: заметки GM, скрытые узлы, связи «только
GM». Поэтому кнопка экспорта есть только у GM.

## data

- `nodes[]` — узлы: `id`, `type` (`actor` / `placeholder` / `image`), `actorId`, `name`,
  `originalName`, `img` (пустая строка — картинка по умолчанию), `imageSource` (`portrait` / `token`, у узла с актёром;
  нет — `portrait`), `imageFit` (`cover` / `contain` / `fill` / `scale-down`; нет — `cover`),
  `imageAlign` (`top-left`, `top-right`,
  `center`, `bottom-left`, `bottom-right`; нет или неизвестное — `center`), `x`, `y`, `scale`,
  `primaryFactionId`, `factionIds`, `role`, `lore`, `playerNotes`, `gmNotes`, `conditions`
  (id состояний), `hidden`, `gmOnly`.
- `edges[]` — связи: `id`, `source`, `target`, `label`, `directional`, `relationshipTypeId`
  (`""` — без типа), `gmOnly`.
- `factions[]` — `id`, `name`, `color`, `description`.
- `relationshipTypes[]` — `id`, `label`, `color`, `dash` (`""` — сплошная линия).
- `conditions[]` — только **свои** состояния (`id`, `label`, `icon`); встроенные живут в коде
  и в файл не попадают.
- `background` — фон графа (необязательное поле; нет или `null` — стандартный фон): `color`
  (`""` — стандартный цвет), `image` (путь, `""` — без картинки), `imageMode` (`single` — общее
  изображение, `tile` — текстура, `screen` — на весь экран, неподвижно), `imageX`, `imageY`
  (левый верхний угол / точка привязки плиток, в координатах графа; у `screen` не используются),
  `imageWidth` (ширина картинки или плитки в единицах графа, `0` — натуральная; у `screen` не
  используется), `imageOpacity` (0–1), `font` (шрифт подписей узлов и связей; `""` или нет —
  Signika), `factionDisplay` (`badges` — дополнительные фракции ромбиками на узле, `areas` —
  узел входит в области всех своих фракций; нет или неизвестное значение — `badges`),
  `factionBlend` (`overlay` — области слоями, `mix` — смешение цветов в перекрытии; нет или
  неизвестное значение — `overlay`). Файлы без этого поля (модуль 1.0.0) читаются как есть.

## Что делает импорт

Файл проходит те же нормализации, что и граф при загрузке из хранилища, плюс проверку ссылок.
Всё, что починено или пропущено, попадает в предупреждения (уведомление + консоль):

- элементы без строкового `id` и повторяющиеся id пропускаются;
- связи на несуществующие узлы пропускаются, неизвестный тип связи сбрасывается в «без типа»;
- неизвестные фракции у узла отбрасываются, основная фракция приводится к общему правилу (основная — первая из отмеченных);
- неизвестный `type` узла — `placeholder`; `actor` без `actorId` — тоже `placeholder`;
- `scale` приводится к диапазону 0.3–5.0;
- неизвестные состояния узлов попадают в справочник, недостающие стандартные типы связей
  (`ally`, `enemy`, `family`, `hierarchy`, `quest`, `romantic`, `unknown`) дописываются
  с пустым `label` (название переводится при показе), `hidden` включает `gmOnly`;
- встроенные состояния в `conditions` файла игнорируются;
- у фона неизвестный `imageMode` — `single`, неверные числа — значения по умолчанию; фон без
  цвета и картинки — стандартный.

Импорт заменяет граф целиком и отменяется через `Ctrl` + `Z`.
